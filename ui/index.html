Encrypt and decrypt

Text passes through two stages. Stage 1 substitutes letters with a repeating keyword; stage 2 reorders them on a zig-zag fence. Decryption undoes the stages in reverse order.

Attack lab

The attacker knows the design but not the keys. The known-plaintext attack tries every rail count, reverses the fence and reads the keyword off by modular subtraction. A consistent repeating keyword means the guess is right.

Design and security

How the two classical techniques are combined, why the combination is stronger than either one alone, and why it still breaks.

Ciphertext

Vigenère is a substitution: it changes what each letter is, using C = (P + K[i mod m]) mod 26. Rail Fence is a transposition: it changes where each letter sits by writing the text down and up across the rails and reading row by row. Combining a substitution with a transposition is the classical idea behind product ciphers: confusion from the first stage, diffusion of position from the second.

Decryption runs the inverse stages in reverse order: undo the fence first, then subtract the keyword. The secret key is the pair (keyword, rails).

Security analysis

  • Single-letter frequency analysis fails. The keyword uses m different shifts, so the ciphertext histogram is flattened and the index of coincidence drops from about 0.066 towards 0.038.
  • Kasiski and column attacks are disrupted. They need letters that were enciphered with the same key letter to sit m positions apart. The fence moves them, so they only reappear after the right rail count is guessed.
  • The rail key is tiny. There are only about n − 1 useful rail counts, so an attacker simply tries them all. The real key space is roughly 26m × n, but the two parts can be attacked one after the other.
  • Known plaintext breaks it in milliseconds. With a little more than m known letters, every wrong rail guess produces a contradictory keyword and the right one stands out.
  • Long ciphertext breaks it without any plaintext. With a few hundred letters of English, per-column chi-squared scoring over every rail count recovers both keys.

HCC is an educational cipher. It must never protect real data; modern systems use AES-GCM or ChaCha20-Poly1305.

Cheap improvements

  • Replace Rail Fence with a keyed columnar transposition, so the permutation depends on a secret word rather than one small number.
  • Apply the Vigenère stage again after the transposition. Known plaintext then no longer lines up with a single key letter.
  • Use an autokey Vigenère, so the key stream is as long as the message and does not repeat with period m.
  • Choose long random keywords instead of dictionary words.
  • Each change keeps encryption and decryption O(n).
